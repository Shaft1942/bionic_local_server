1. UTILISATION DANS COMFYUI

Ouvrir le fichier *.workflow.json souhaité avec Ctrl+O ou le déposer sur le canevas.
Modifier le prompt, puis cliquer sur Exécuter lorsque tu souhaites lancer le rendu.
Les *.api.json servent aux appels HTTP ; les *.workflow.json conservent les nœuds
et leur présentation éditable. Aucun poids de modèle n'est inclus dans ce paquet.

Commencer par 02-Krea2-Turbo.workflow.json pour la photographie ou par
01-Hassaku-Illustrious.workflow.json pour l'illustration. Le prompt de démonstration
est un adulte botaniste dans une serre. Il est remplaçable et ne vient pas de tes
presets privés. Seeds fixes à 42, lot de 1.

3. PRÉPARER UNE REQUÊTE POUR BIONIC OU LE COMPAGNON

manifest.json décrit les profils et lie chaque paramètre à un node_id et au nom
de son entrée. Les noms de fichier, modèles, sampler, steps, CFG et lot sont fixés.
Formats proposés : square 1024x1024, portrait 832x1216, landscape 1216x832.
Ces plafonds sont des choix de passerelle, pas des limites intrinsèques des modèles.
Seeds limitées à 32 bits pour éviter les pertes de précision entre Python et JS.

Depuis le dossier extrait du paquet, exemple HORS LIGNE :

python preparer_requete.py --workflow krea2_turbo --prompt "A blue ceramic teapot on a limestone table, soft morning light." --seed 42 --format square --output demande.json

Ce programme Python standard (sans installation de dépendances) écrit une enveloppe
avec les paramètres, l'empreinte du workflow et le corps HTTP. Il ne contacte aucun
serveur et refuse d'écraser une demande déjà présente.
Le profil expérimental exige --allow-experimental et --krea-prompt explicitement.

Pour lancer réellement LE RENDU depuis PowerShell, après préparation de demande.json :

$demande = Get-Content -LiteralPath '.\demande.json' -Raw | ConvertFrom-Json
$corps = $demande.body | ConvertTo-Json -Depth 30 -Compress
$octets = [System.Text.Encoding]::UTF8.GetBytes($corps)
$reponse = Invoke-RestMethod -Uri 'http://127.0.0.1:8188/prompt' -Method Post -ContentType 'application/json; charset=utf-8' -Body $octets
$reponse

Conserver le prompt_id retourné. Puis consulter sans relancer :

Invoke-RestMethod -Uri ('http://127.0.0.1:8188/history/' + $reponse.prompt_id)

Un historique encore vide n'est pas un échec. Attendre l'état terminal. Consulter
/queue si nécessaire ; ne pas soumettre une deuxième fois après un délai expiré.
Le POST /prompt ajoute réellement à la file ; il ne faut pas l'utiliser comme dry-run.
Les sorties SaveImage se trouveront sous le dossier output configuré de ComfyUI,
dans Bionic/Hassaku, Bionic/Krea2 et Bionic/Hassaku-vers-Krea2.

4. CE QUI RESTE POUR LE COMPAGNON RÉSEAU

Le compagnon courant v1.10.0 possède déjà une boucle d'outils fichiers/web/scripts,
selon les sources et preuves d'audit relues dans ce workspace. Notre ancienne
description « il faut créer la boucle d'outils » était donc dépassée.
Il reste à ajouter un outil ComfyUI dédié et la présentation des images.
Aucun fichier du compagnon ou de Bionic n'a été modifié dans cette préparation.

Contrat conseillé : submit_comfy_generation(workflow_id, prompt, seed, format), puis
get_comfy_generation(job_id). Conserver job_id/prompt_id et les états queued,
running, succeeded, failed, unknown ; pas de relance automatique d'un POST incertain.
Le compagnon doit recevoir body dans l'enveloppe, pas toute l'enveloppe à la place
du graphe. La requête POST est {prompt:graphe_API, client_id:identifiant}.
Récupérer les fichiers via /view avec filename, subfolder et type réellement fournis
par l'historique. Le compagnon sert ensuite les images au téléphone avec une URL
relative à son propre serveur : un lien 127.0.0.1:8188 viserait le téléphone.
Respecter les validations actuelles des scripts du compagnon ; ne pas les contourner.

Ne pas décharger ou reconfigurer Bionic automatiquement. Laisser ComfyUI gérer
l'offload, garder lot1, puis mesurer la coexistence des deux moteurs en génération.
Le paquet ne modifie ni les ports, ni le pare-feu, ni les paramètres mémoire.
Utiliser l'adresse loopback côté passerelle n'a pas modifié l'exposition réseau
actuelle de ton ComfyUI, qui écoutait déjà sur toutes les interfaces lors du relevé.
