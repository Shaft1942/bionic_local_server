# Préparation et validation 2.1.0

Cette branche prépare une version ; sa présence ne signifie ni publication GitHub, ni mise à jour de l’installation utilisée sur le téléphone.

## Intégration

Base : Release publique 2.0.0, commit `f47adbf`. Les certificats sont intégrés avec les corrections Windows de mise à jour de cette base. La configuration, les conversations et les processus des installations utilisées restent séparés des essais.

Périmètre : gestion des certificats dans le navigateur, port de preuve fixe provisionné à l’installation, curseur de tokens jusqu’à 5 millions conservé, chargement réel du contexte avant contrôle du message, module ComfyUI distribué et récupération après erreur.

## Contrôles

Sur la branche intégrée, le 22 octobre 2026, sous Windows et Node.js 24 :

- **536/536 tests Node réussis**, aucun ignoré, avec concurrence limitée à deux fichiers et TEMP unique hors synchronisation. La suite comprend les workers de mise à jour réels en TLS/mTLS et les récupérations après échec.
- **2/2 tests Python** du module ComfyUI réussis ; **101 sources JavaScript** vérifiées.
- Inventaire de distribution : **196 sources publiques**, données privées et fichiers de certificats exclus. L’archive contient le module ComfyUI et ses instructions.
- Navigateur V2 à **1 280 et 320 px** : saisie et curseur synchronisés de 1 à 5 millions, préférences et LoRA conservés.
- Parcours certificats à **1 440 et 390 px** : préparation, téléchargement `.p12`, disparition du mot de passe à la fermeture et contrôle des débordements. Les réponses tardives après fermeture sont ignorées.
- **Chromium réel à 390 px** sur une fixture isolée : POST HTTP de départ, POST vers le candidat HTTPS, confirmation HTTPS. Origin et CSP sont conservés ; aucun ticket dans une URL. La confiance du navigateur est limitée à la clé de cette fixture et à ce seul processus ; la chaîne TLS est validée séparément par les tests Node.
- **Quatre aperçus WinForms** générés sans installation, avec les champs de port et l’autorisation initiale des deux ports. Vérification PowerShell du périmètre Programme/Adresse/Sous-réseau/Interface/Profil/Ports avec des commandes réseau simulées.

Les contrôles du chargement de modèles et de ComfyUI utilisent des endpoints simulés. Les tests de transport utilisent TLS/mTLS natif et de vrais certificats éphémères, sans installation dans les magasins de confiance du PC. Les scripts d’installation et le worker détaché sont exécutés sur des fixtures Windows uniquement.

## Répétition Windows sur archive

Les cinq scénarios exécutés avec le véritable helper d’installation et le worker détaché ont réussi :

1. Installation neuve du ZIP 2.1, démarrage authentifié et quatre aperçus de l’assistant.
2. Installation depuis l’archive publique 2.0 (`a6e1ec1e…`), puis mise à jour HTTP vers 2.1.
3. Ancienne branche privée de certificats basée sur 2.0 (`2072397`), puis mise à jour HTTPS vers 2.1.
4. Même branche privée, mise à jour mTLS vers 2.1.
5. Échec de remplacement provoqué par un verrou Windows permanent, puis retour aux sources précédentes et redémarrage mTLS.

La branche privée des scénarios 3 à 5 est distincte de la Release publique 2.0, qui n’incluait pas encore les certificats. Dix fichiers privés pour le parcours HTTP, dix-huit pour les parcours PKI, sont conservés octet par octet : configuration, identité, conversations, livrables et certificats. Le document des adresses est inchangé pour la 2.0 publique ; dans les scénarios PKI, seuls ses blocs générés de connexion et d’aide sont actualisés, avec code inchangé. Les connexions HTTP sont refusées en TLS ; l’absence de certificat client et une identité révoquée sont refusées en mTLS.

Les sources installées ou restaurées correspondent aux octets attendus. Les neuf serveurs et quatre workers créés pour la recette ont été arrêtés ; aucun appel Bionic/ComfyUI réel n’a été effectué. Le ZIP testé portait l’empreinte `26fe5cb5e889c9cdb946aa2871a7cbeaa4ac579d609d2fccf7cb58f0b5fc1430`. La finalisation de ce registre et la stabilisation du seul test de checkpoint sont les différences de la dernière archive ; les 194 autres sources sont comparées octet par octet et identiques. Le code exécuté du compagnon, de l’installation et de la mise à jour est donc identique à celui de la recette.

Le test de sauvegarde d’une réponse déconnectée attend maintenant une condition observable sur le JSON persistant, avec une échéance bornée, plutôt qu’une pause fixe de 1 100 ms. Il vérifie toujours le texte partiel et l’état en cours avant toute commande d’arrêt ; une sauvegarde absente reste un échec. La vérification ciblée passe aussi avec un checkpoint volontairement retardé à 1 500 ms dans un processus de test, sans modifier le serveur.

## Limites

- Aucun chargement/déchargement réel de modèle ni rendu ComfyUI n’est déclenché par cette validation. Le gain de vitesse doit être mesuré séparément à prompt, seed, workflow et configuration identiques.
- Les captures mobiles utilisent un navigateur de bureau redimensionné. L’importation physique d’un certificat et sa confiance Android/iOS restent à essayer sur l’appareil.
- Les règles de pare-feu sont vérifiées avec de vrais scripts PowerShell et des commandes Windows simulées. Aucune règle réelle ni demande UAC n’est déclenchée pendant les essais.
- L’activation et la révocation testées utilisent seulement une PKI synthétique. Aucun certificat ni code privé d’une installation existante n’est changé.
